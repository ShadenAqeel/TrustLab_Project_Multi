# TrustLab — Playable ML Website (MVP)

This is a **working full-stack implementation** of the TrustLab web experience.
It preserves the supplied supervised/unsupervised research models, notebooks and
original data. Visitors play repeated Prisoner's Dilemma rounds with real next-
move predictions generated by the trained Logistic Regression, then receive a
K-Means behavioral profile. Opponents are simulated; there are no human players
on the other side of the site.

## Contents

- Landing page: scientific storytelling, custom animated SVG decision network.
- Experiment setup: fixed or changing simulated opponents; 12 or 25 rounds;
  Challenge (post-round predictions) or Research (predictions only at report).
- Arena: simultaneous-choice round, 3/0/4/1 payoff matrix, locked AI prediction
  and opponent choice before the player move, deterministic scoring, progress.
- Reveal: real unsupervised profile, player metrics, round timeline, sealed
  predictions and clearly labeled **preliminary** clustering interpretation.
- Research Lab: aggregates and original exported scientific figures.
- API: FastAPI + existing `trustlab_unsupervised` package + two saved .joblib models.
- Tests: 16 backend tests and a manually exercised 12-round browser workflow.

## Run locally on Windows (recommended: Python 3.12)

Open PowerShell in this project directory:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --reload --host 127.0.0.1 --port 8000
```

Now visit **http://127.0.0.1:8000** in your browser.

If Windows does not recognize `py -3.12`, install Python 3.12 first.
**Node/npm is NOT needed to run the included prebuilt website.**

## Run locally on macOS / Linux

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-web.txt
```

## One-container deployment

The Dockerfile runs the API and serves the prebuilt React UI **on one origin**,
so there is no separate frontend/CORS configuration.

Build and run:

```bash
docker build -t trustlab .
docker run --rm -p 8080:8080 trustlab
```

Visit `http://localhost:8080`.

To use Render, push this directory as a Git repository and create a new **Web
Service** using the repository's Dockerfile (or Render Blueprint using
`render.yaml`). Set the health-check path to `/api/health`; the app honors
`PORT`. Check Render's latest instance availability and pricing before starting
any paid plan. The included blueprint requests the free plan.

**Limitations of the current deployment design:**
- Game sessions use a process-local, anonymous in-memory store. They disappear
  after server restart, sleep or redeploy; deploy **one worker only**.
- Stored game records expire after 4 hours. There is no cross-instance store.
- The frontend is a self-contained offline-built **React** MVP. This sandbox
  couldn't reach npm, so it uses a local legacy React UMD runtime and an
  explicit compatibility layer for hooks. Before **long-term public exposure**,
  update the frontend to a maintained React release with Vite, then integrate
  `motion-framer`, GSAP/ScrollTrigger and R3F as laid out in the included
  `docs/TRUSTLAB_WEB_BUILD_SPEC.md`. CSS/SVG motion is implemented now; the
  advanced animation/3D libraries have not been installed in this build.
- The original joblib artifacts were created with **scikit-learn 1.6.1**. Our
  preview runtime used 1.8.0 with a narrow deserialization compatibility shim,
  but the Docker deployment intentionally pins 1.6.1. The Docker image has
  not been built inside this network-restricted environment.
- Short sessions cannot give a scientifically validated long-history strategy
  label. The UI always says exploratory / preliminary. Relative cluster
  closeness scores are not calibrated probabilities.
- No personal demographic data or survey responses are sent to the browser.

## API contract

- `GET /api/health` — model readiness
- `POST /api/game/start` — `{"treatment":"fix"|"rand","rounds":12|25,"feedback":"challenge"|"research"}`
- `GET /api/game/{id}` — replay-safe public session state, without sealed actions
- `POST /api/game/{id}/round` — `{"move":"C"|"D","request_id":"<uuid>"}`
- `GET /api/game/{id}/results` — final report, only when finished
- `GET /api/research/summary` — aggregated real research information

The web API does not upload or load user-supplied joblib files. Each round's
prediction and simulated opponent choice are created from completed history
**before** the player's move is submitted. Retries using the same request UUID
return the same round response and never double-score the game.

## Scientific notes

- Original source: https://doi.org/10.5061/dryad.37pvmcvmk
- Strategy model: five cooperation/conditional cooperation features, K-Means
  k=4, fitted to the original dataset's 100-round player histories.
- Predictive model: integrated Logistic Regression trained on historical player
  decisions; model is not retrained during visitor gameplay.
- Browser experience: synthetic, stochastic memory-one opponent policies
  initialized from research cluster centroid rates. In the changing-partner
  condition, a new opponent policy is drawn each round and has no prior personal
  history with the visitor. This is an educational simulation, **not the
  original human experiment**.
- `docs/TrustGame_plan.pdf` is the original (outdated) pre-integration plan; the
  current code, `docs/PROJECT_NOTES.md`, and the web build spec take precedence.
